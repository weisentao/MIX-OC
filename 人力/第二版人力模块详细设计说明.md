# 第二版人力模块详细设计说明

> 本目录当前保留的是“第二版”人力模块预览图。第二版的方向是：在现有项目管理系统里增加一个“人力排期 / 人力资源视角”，帮助项目经理查看公司人员当前任务、空闲时间、负载风险，并把新任务安排给合适的人。
>
> 本文档用于给项目经理、产品、前端、后端交接。当前只提供设计预览和实施说明，不包含 HTML，也没有修改现有业务代码。

## 2. 第二版总体定位

“人力”不是传统 HR，不做薪资、绩效、考勤。它是项目管理系统里的资源排期能力。

它要解决三个问题：

1. **谁在做什么**：每个人当前负责哪些项目、任务、排期项。
2. **谁什么时候有空**：哪些人在某个日期范围内可接新任务。
3. **新任务给谁合适**：根据部门、技能、时间冲突、当前负载推荐负责人。

第二版设计重点：

- 保持“项目管理工作台 + 时间轴”的产品形态。
- 复用现有排期模块的视觉语言：左侧导航、顶部提示、时间轴、颜色任务条、浮窗。
- 把人力数据叠加到排期视图中，而不是重新做一个孤立系统。
- 重点给项目经理排活使用，不做复杂 HR 管理。
- 不同角色看到的是同一套人力能力的不同数据范围，前端不能把所有视角入口默认暴露给所有人。

## 2.1 角色和视角总原则

第二版人力模块必须按“角色 + 数据范围”控制可见内容。这里的重点不是做多套页面，而是在同一套页面框架下，根据当前登录人的身份裁剪视角入口、部门范围、人员范围和可操作按钮。

### 2.1.1 角色定义

| 角色 | 业务含义 | 默认可见范围 |
| --- | --- | --- |
| 超级管理 `super_admin` | 老板、系统超级管理员、公司级负责人 | 全公司、全部部门、全部项目、全部人员。 |
| 管理 / 项目管理 `manager` / `project_manager` | 项目总负责人、项目经理、被授权的管理人员 | 自己负责或被授权的项目，以及项目涉及的部门和人员；如果公司配置为管理层全局可见，也可开放全公司视图。 |
| 部门管理者 `department_manager` | 美术设计部、AIGC、三维动画、后期合成等部门负责人 | 自己负责的部门；如果一个人负责多个部门，只能在这些部门之间切换。 |
| 个人 / 普通员工 `employee` | 普通成员、执行人员 | 只能看自己的个人视角和自己参与的任务，不允许浏览部门或全公司人力。 |

### 2.1.2 视角可见规则

| 视角入口 | 超级管理 | 管理 / 项目管理 | 部门管理者 | 普通个人 |
| --- | --- | --- | --- | --- |
| 超级管理视角 | 可见 | 按授权可见 | 不可见 | 不可见 |
| 项目管理视角 | 可见 | 可见 | 只在参与项目内局部可见，不显示为全局入口 | 不可见 |
| 部门管理者视角 | 可见，可切全部部门 | 可见，可看项目相关部门 | 可见，只能看自己部门 | 不可见 |
| 个人视角 | 可看所有人 | 可看负责项目内成员 | 可看本部门成员 | 只能看自己 |
| 空闲池 | 全公司空闲池 | 授权项目/部门空闲池 | 本部门空闲池 | 不可见 |
| 交互完成态 | 可见全部分配结果 | 可见自己负责范围 | 可见本部门分配结果 | 只看和自己有关的结果 |

### 2.1.3 前端显示原则

- 没有权限的视角入口建议直接隐藏，不建议只置灰，避免普通员工误以为可以申请查看全公司人力。
- 部门管理者登录时，左侧只显示“部门管理者视角、个人视角、空闲池、本部门人员树”；不显示“超级管理视角”。
- 普通个人登录时，左侧只显示“个人视角”和自己的任务/空闲信息；不显示部门列表、全公司统计、空闲池和批量分配动作。
- 超级管理和管理角色可以看到更多视角切换，但每次切换都必须由后端按权限重新返回数据，不能只靠前端隐藏字段。
- 如果同一个账号同时拥有多个身份，按最高身份开放视角，但数据范围仍要受授权项目/部门限制。

## 3. UI 风格要求

第二版比第一版更适合保留，因为它兼顾了“更清楚”和“更像产品功能”。

### 3.1 视觉关键词

- 浅色工作台
- 左侧功能导航
- 顶部项目提醒条
- 高密度时间轴
- 部门/人员树
- 绿色空闲、黄色接近满载、红色风险
- 右侧浮动聊天/详情窗
- 圆角轻卡片，但不要过度 dashboard 化

### 3.2 颜色语义

| 颜色 | 含义 | 使用位置 |
| --- | --- | --- |
| 绿色 | 正常、可安排、空闲、已确认 | 空闲任务条、推荐人员、成功状态 |
| 黄色 | 接近满载、待分配、需要关注 | 接近满载人员、待处理任务 |
| 红色 / 粉色 | 超负荷、冲突、高风险、品牌强调 | 风险任务条、二次确认、当前选中入口 |
| 蓝色 | 信息提示、备选、系统动作 | 次级推荐、搜索/工具动作 |
| 紫色 | 节点/特殊模块 | AIGC 或节点视图辅助色 |

### 3.3 信息密度

人力模块要像排期页面一样“信息密度高”，不能只放几个大卡片。

建议比例：

- 时间轴区域占页面宽度和高度的主体。
- 统计卡片只作为辅助，不能抢主视觉。
- 人员/部门列表和时间轴必须同步滚动或至少视觉对齐。
- 浮窗只在选中人员/任务时出现，避免默认遮挡太多内容。

## 4. 各界面详细说明

## 4.1 超级管理 / 项目管理视角

对应图片：`05-新版超级管理人力总览.png`

### 目标用户

- 老板
- 超级管理员
- 项目总负责人
- 同时管理多个部门的人

### 可见权限

这个页面只给超级管理和管理 / 项目管理角色开放。

- 超级管理：看全公司全部部门、全部项目和全部人员。
- 管理 / 项目管理：看自己负责或被授权的项目范围；如果业务上授权为公司级管理，可以看全公司。
- 部门管理者：默认不能进入这个视角，只能进入部门管理者视角。
- 普通个人：不能进入这个视角。

### 核心用途

从全公司角度看：

- 哪些部门正在忙。
- 哪些人员超负荷。
- 哪些人员有空闲窗口。
- 哪些任务没人负责。
- 新任务应该优先安排给谁。

### 页面结构

1. **左侧功能栏**
   - 首页
   - 排期
   - 流程
   - 画板
   - 人力
   - 优化

2. **左侧人力筛选区**
   - 视角切换：超级管理视角、项目管理视角、部门管理视角、个人视角、空闲池、交互完成态。
   - 视角切换要按权限动态渲染，图片里展示的是超级管理 / 管理角色可见状态，不代表普通个人也能看到。
   - 部门/人员列表：项目管理、美术设计、AIGC、三维动画、后期合成等；管理角色只能看到授权范围内的部门和人员。
   - 今日空闲提醒：例如“8 人可接新活，3 人超负荷”。

3. **顶部项目提醒区**
   - 保留当前系统的项目提醒文案。
   - 用于提示风险任务优先处理。

4. **主体时间轴**
   - 按部门分组。
   - 每个人一行。
   - 横向是日期。
   - 任务条表示占用。
   - 空闲以浅绿色窗口或留白体现。

5. **右侧浮动沟通窗**
   - 选中人员或任务后出现。
   - 展示该人员当前负载、沟通记录、系统建议。

### 关键交互

- 点击部门：只看该部门人员。
- 点击人员：进入个人视角或打开右侧详情浮窗。
- 点击任务条：打开任务详情/评论/分配建议。
- 拖动任务条：后续可支持调整日期，但第一期可先不做。
- 点击“空闲优先”：按可接活人员排序。

### 项目经理价值

这个视图适合开会时看全局，不适合做精细编辑。它回答：“当前公司资源整体够不够，风险在哪”。

### 前端复刻注意

- `05-新版超级管理人力总览.png` 可以继续作为超级管理 / 管理角色的主参考图。
- 前端实现时要把“超级管理视角”和“项目管理视角”作为有权限门槛的入口。
- 如果当前账号不是超级管理或管理角色，不能通过 URL 直接访问这个视图；后端也要返回无权限。

## 4.2 部门管理者视角

对应图片：`06-新版部门经理人力视图.png`

### 目标用户

- 美术设计部负责人
- AIGC 负责人
- 三维动画负责人
- 后期合成负责人
- 任何只管理本部门的人

### 可见权限

这个页面给部门管理者使用，也可以被超级管理和管理角色进入查看。

- 超级管理：可切换查看任意部门。
- 管理 / 项目管理：可查看自己负责项目涉及的部门，或被授权的部门。
- 部门管理者：只能查看自己负责的部门；例如美术设计部负责人只能看到美术设计部，不应看到 AIGC、三维动画、后期合成的完整人员负载。
- 普通个人：不能进入部门管理者视角。

### 核心用途

只看本部门人员，做日常排活。

例如美术设计部经理要知道：

- 王月能不能接活动页资源补齐。
- 朱敏是否超负荷。
- 老马什么时候能做图标。
- 周宁是否能支援切图。

### 页面结构

1. **左侧部门状态卡**
   - 部门人数。
   - 可接新活人数。
   - 超负荷人数。
   - 本周空闲窗口数量。

2. **候选人员卡片**
   - 王月：推荐。
   - 老马：可选。
   - 朱敏：不建议。

3. **部门时间轴**
   - 只展示当前部门成员。
   - 每个成员一行。
   - 绿色任务条为正常安排。
   - 红色/黄色提示风险或接近满载。

4. **部门经理动作区**
   - 一键找空闲。
   - 转移冲突任务。
   - 导出部门负载。

### 关键交互

- 选择日期范围，查看某段时间部门资源。
- 点击候选人，查看该候选人的时间轴和推荐原因。
- 点击待分配任务，自动匹配部门内可用人员。
- 点击“转移冲突任务”，进入重新分配流程。

### 项目经理价值

这个视图适合部门负责人每天使用，是第二版里最实用的工作视图。

### 前端复刻注意

- `06-新版部门经理人力视图.png` 是“部门管理者视角”的模板图，不是只代表美术设计部。
- 美术设计、AIGC、三维动画、后期合成等部门都按这个结构复刻，只替换部门名称、部门人员、部门统计、候选人和任务条数据。
- 部门管理者不能看到左侧完整公司部门树；如果保留树形结构，只显示自己负责部门以及部门内人员。
- 部门管理者可以看到本部门项目任务和排期，但不应该看到其他部门的完整任务明细。

## 4.3 个人视角

对应图片：`07-新版个人视角-朱敏.png`

### 目标用户

- 项目经理查看某个人。
- 部门经理查看某个成员。
- 员工查看自己的安排。

### 可见权限

个人视角是所有角色都会用到的最小视角，但不同角色能打开的人不同。

- 超级管理：可查看任意人员的个人视角。
- 管理 / 项目管理：可查看自己负责项目内成员的个人视角。
- 部门管理者：可查看本部门成员的个人视角。
- 普通个人：只能查看自己的个人视角，不能通过搜索、URL 或人员列表打开别人。

### 核心用途

单独回答一个人的情况：

- 这个人现在在做什么。
- 哪些任务已经占满。
- 哪天有空。
- 还能不能继续安排任务。

### 页面结构

1. **个人资料区**
   - 头像/首字。
   - 姓名。
   - 部门和岗位。
   - 当前负载，例如 118%。

2. **负载日历/热力图**
   - 用颜色表现一段时间内忙闲情况。
   - 红色代表超负荷。
   - 绿色代表可安排。

3. **当前任务列表**
   - 当前正在做的任务。
   - 高优先级任务。
   - 未来任务。

4. **个人时间轴**
   - 按任务类型展示占用。
   - 单独展示空闲窗口。
   - 单独展示会议/沟通等固定占用。

5. **人力建议区**
   - 不建议继续追加任务。
   - 可安排半天复核。
   - 可拆给其他成员。

6. **浮动沟通窗**
   - 绑定当前人员。
   - 可以看任务沟通和本人反馈。

### 关键交互

- 点击个人头像：打开个人资料。
- 点击任务条：查看任务详情。
- 点击空闲窗口：发起安排任务。
- 点击“打开沟通/调整排期”：进入协作处理。

### 项目经理价值

这个视图适合在安排具体任务前确认某个人是否真的有空，避免只看名字就压任务。

### 前端复刻注意

- `07-新版个人视角-朱敏.png` 可作为个人视角模板，朱敏只是示例人员。
- 普通个人登录时，应把左侧人力筛选区简化为个人信息、我的任务、我的空闲窗口，不显示全公司部门树。
- 如果是部门管理者或项目管理者从人员列表点进来，可以保留返回部门/项目视图的入口。
- 普通个人不展示“推荐分配”“转移冲突任务”“强制分配”等管理动作。

## 4.4 新建任务推荐人力

对应图片：`08-交互流程1-新建任务推荐人力.png`

### 使用场景

项目经理要新增一个任务，例如“活动页资源补齐”。

### 可见权限

- 超级管理：可在全公司范围内发起推荐，但仍建议优先按项目部门筛选。
- 管理 / 项目管理：可在自己负责或被授权项目内发起推荐。
- 部门管理者：可在自己部门内发起推荐，不能把任务直接分配给其他部门人员，除非项目权限另有授权。
- 普通个人：不开放新建任务推荐人力入口。

### 页面结构

左侧是任务信息：

- 任务名称。
- 项目。
- 开始日期。
- 结束日期。
- 所需部门。
- 优先级。

中间是空闲人员池：

- 推荐人员。
- 负载百分比。
- 空闲原因。
- 是否技能匹配。

右侧是冲突预览：

- 分给王月后的占用情况。
- 分给朱敏后的冲突情况。
- 分给老马后的可行性。

### 推荐逻辑

系统至少要考虑：

1. 时间是否冲突。
2. 当前负载是否过高。
3. 部门是否匹配。
4. 技能是否匹配。
5. 是否已有高优先级任务。
6. 是否连续多天被占用。

### 推荐输出

候选人要有解释，不能只给分数。

示例：

- 王月：有 3 个连续空闲日，技能匹配 UI，推荐。
- 老马：负载 64%，可承接图标补齐，备选。
- 朱敏：当前 118%，不建议继续安排。

## 4.5 确认分配完成

对应图片：`09-交互流程2-确认分配完成.png`

### 使用场景

用户确认把任务分配给王月。

### 可见权限

- 超级管理：可确认全公司范围内的任务分配。
- 管理 / 项目管理：可确认自己负责项目内的任务分配。
- 部门管理者：可确认本部门成员承接的任务；涉及跨部门人员时需要项目管理或超级管理确认。
- 普通个人：不能确认给别人分配任务，最多只能确认自己接收或反馈任务。

### 完成态要展示

1. 顶部成功提示。
2. 王月时间轴出现新的任务条。
3. 写入结果区显示：
   - 负责人。
   - 任务。
   - 时间。
   - 同步结果。
4. 后续提醒：
   - 通知王月。
   - 通知原负责人或相关人员。
   - 提醒项目经理检查交付状态。

### 写入规则

确认分配时不建议创建新的事实源。

应该复用已有任务/排期更新能力：

- 普通任务：更新任务负责人、时间、状态。
- 排期项：更新排期项负责人、时间、状态。
- 如果任务和排期项有关联，要避免重复写入或重复计算负载。

## 4.6 超负荷二次确认

对应图片：`10-交互流程3-超负荷二次确认.png`

### 使用场景

用户仍然想把任务分配给朱敏，但朱敏已经超负荷。

### 二次确认内容

弹窗必须明确说明：

- 当前负载是多少。
- 分配后负载是多少。
- 会冲突几条任务。
- 推荐替代人员是谁。

### 按钮建议

- 取消。
- 改给推荐人员，例如“改给王月”。
- 仍然分配。

### 权限建议

普通员工不能强行分配给超负荷人员。

建议规则：

| 角色 | 是否可强行分配 |
| --- | --- |
| 超级管理 `super_admin` | 可以，但必须填写原因并记录日志 |
| 管理 / 项目管理 `manager` / `project_manager` | 可以，但必须二次确认，并限制在负责项目范围内 |
| 部门管理者 `department_manager` | 建议默认不允许强制跨部门分配；本部门内可按公司规则二次确认 |
| 普通个人 `employee` | 不允许 |

## 6. API 建议

### 6.1 人力池接口

```http
GET /workspace/resources?department=&q=&status=active
```

返回：

- 人员列表。
- 部门列表。
- 人员角色。
- 人员岗位。
- 项目成员身份。
- 当前登录人的人力模块权限 `resourcePermissions`。
- 当前登录人的可见范围 `scope`，例如公司、项目、部门或本人。

后端要求：

- 超级管理可返回全公司部门和人员。
- 管理 / 项目管理只返回授权项目或部门内人员。
- 部门管理者只返回自己负责部门和部门成员。
- 普通个人只返回自己，不返回完整部门树。

### 6.2 负载接口

```http
GET /workspace/workload?from=2026-05-10&to=2026-06-14&projectId=&department=&userId=
```

返回：

- people：人员。
- workItems：任务和排期项。
- availability：空闲窗口。
- conflicts：冲突。
- permissions：当前数据范围下可执行的操作，例如能否分配、能否强制分配、能否导出。

后端要求：

- 查询参数里的 `department`、`projectId`、`userId` 不能突破当前登录人的 `scope`。
- 如果普通个人传入别人的 `userId`，接口应返回无权限，而不是返回空数据伪装成功。
- 如果部门管理者传入其他部门 `departmentId`，接口应返回无权限。

### 6.3 分配预览接口

```http
POST /workspace/assignments/preview
```

请求：

- 任务名称。
- 项目 ID。
- 日期范围。
- 部门。
- 技能标签。
- 候选人。

返回：

- 推荐人。
- 推荐分。
- 冲突数。
- 分配前负载。
- 分配后负载。
- 推荐原因。

后端要求：

- 候选人必须在当前登录人的可分配范围内。
- 部门管理者默认只推荐本部门人员。
- 管理 / 项目管理推荐范围来自负责项目和授权部门。
- 普通个人不能调用该接口创建给别人分配任务的预览。

## 8. 权限设计

权限是第二版落地时最容易误解的点。前端复刻图片时要注意：图片展示的是“目标视觉形态”，不是所有角色都能看到所有入口。

### 8.1 角色权限矩阵

| 操作 / 能力 | 超级管理 `super_admin` | 管理 / 项目管理 `manager` / `project_manager` | 部门管理者 `department_manager` | 普通个人 `employee` |
| --- | --- | --- | --- | --- |
| 查看超级管理视角 | 可以 | 按授权可以 | 不可以 | 不可以 |
| 查看项目管理视角 | 可以 | 可以 | 只看参与项目的局部信息，不作为主入口 | 不可以 |
| 查看部门管理者视角 | 可以看全部部门 | 可以看项目相关部门或授权部门 | 只能看自己负责部门 | 不可以 |
| 查看个人视角 | 可以看所有人 | 可以看负责项目内成员 | 可以看本部门成员 | 只能看自己 |
| 查看全公司部门树 | 可以 | 按授权可以 | 不可以，只显示自己部门 | 不可以 |
| 查看空闲池 | 全公司空闲池 | 授权项目/部门空闲池 | 本部门空闲池 | 不可以 |
| 查看超负荷风险 | 全公司 | 授权项目/部门 | 本部门 | 只看自己相关风险 |
| 新建任务推荐人力 | 可以 | 可以 | 只限本部门或授权项目 | 不可以 |
| 确认分配给别人 | 可以 | 可以 | 本部门内可以，跨部门需上级确认 | 不可以 |
| 强制分配超负荷人员 | 可以，必须填原因 | 可以，必须二次确认和记录原因 | 建议默认不开放，或只允许本部门内二次确认 | 不可以 |
| 转移冲突任务 | 可以 | 可以 | 本部门内可以 | 不可以 |
| 导出报表 | 可以导出全公司 | 可以导出授权范围 | 可以导出本部门 | 不可以 |

### 8.2 数据范围规则

同一接口必须根据当前登录人自动收窄数据范围，不能只靠前端隐藏。

| 当前登录人 | 接口默认过滤范围 |
| --- | --- |
| 超级管理 | 不限制部门和项目，除非用户主动筛选。 |
| 管理 / 项目管理 | `projectId in managedProjectIds` 或 `departmentId in authorizedDepartmentIds`。 |
| 部门管理者 | `departmentId in managedDepartmentIds`。 |
| 普通个人 | `userId = currentUserId`。 |

### 8.3 视角入口渲染规则

前端左侧“超级管理视角、部门管理视角、个人视角、空闲池、交互完成态”等入口需要由权限结果驱动。

建议后端返回一个 `resourcePermissions` 对象：

```json
{
  "canViewSuperAdminView": true,
  "canViewProjectManagerView": true,
  "canViewDepartmentView": true,
  "canViewOtherPersonView": true,
  "canViewFreePool": true,
  "canAssignTask": true,
  "canForceAssignOverload": true,
  "scope": {
    "type": "company",
    "departmentIds": [],
    "projectIds": [],
    "userIds": []
  }
}
```

不同角色示例：

| 角色 | `scope.type` | 前端默认进入 |
| --- | --- | --- |
| 超级管理 | `company` | 超级管理视角 |
| 管理 / 项目管理 | `project` 或 `authorized` | 项目管理视角 / 授权的人力总览 |
| 部门管理者 | `department` | 部门管理者视角 |
| 普通个人 | `self` | 个人视角 |

### 8.4 URL 和接口拦截

不能只在页面上隐藏按钮，还要处理用户直接访问 URL 的情况。

- 访问超级管理视角：后端校验 `canViewSuperAdminView`。
- 访问部门管理者视角：后端校验 `departmentId` 是否在 `managedDepartmentIds` 或授权范围内。
- 访问个人视角：后端校验目标 `userId` 是否在可见人员范围内。
- 发起推荐：后端校验任务所属项目、部门和候选人是否都在授权范围内。
- 确认分配：后端校验操作者是否有权修改该任务或排期项。
- 强制超负荷分配：后端必须校验角色，并写入操作原因、操作者、时间和分配前后负载。

## 9. 空闲与负载计算规则

第一期建议用简单规则，保证能解释。

### 9.1 基础规则

- 每人每天默认容量为 1。
- 当天有任务占用，则占用 1。
- 同一天多个任务叠加，负载超过 100%。
- 高优先级任务冲突要标红。
- 已完成、已删除、已归档任务不计入占用。

### 9.2 状态颜色

| 状态 | 规则 | 颜色 |
| --- | --- | --- |
| 空闲 | 负载低于 60% | 绿色 |
| 正常 | 60%-85% | 绿色 |
| 接近满载 | 85%-100% | 黄色 |
| 超负荷 | 超过 100% | 红色 |
| 待分配 | 无负责人或未确认 | 黄色 |

### 9.3 后续增强

后续可以加入：

- 半天容量。
- 小时级工时。
- 请假/会议/培训不可用时间。
- 技能权重。
- 项目优先级权重。
- 人员角色差异，例如主美只承担审核，不承担大量执行。

## 10. 实施阶段建议

### 阶段一：只读看清楚

目标：先让项目经理看见人力状态。

交付：

- 超级管理视角。
- 部门管理视角。
- 个人视角。
- 人员负载颜色。
- 空闲窗口。
- 推荐候选人展示。

不做：

- 拖拽修改任务。
- 强制分配。
- 请假日历。
- 导出报表。

### 阶段二：能安排活

目标：让项目经理可以完成分配。

交付：

- 任务分配侧栏。
- 推荐人员排序。
- 分配完成态。
- 超负荷二次确认。
- 权限控制。
- 写入任务和排期项。

### 阶段三：完整资源管理

目标：从“看人力”升级到“管资源”。

交付：

- 请假/不可用时间。
- 半天/小时容量。
- 导出部门负载。
- 节点关系视图。
- 任务流向复盘。

## 11. 验收清单

项目经理验收时，可以按下面检查：

- 是否能按部门看人力？
- 是否能按个人看任务？
- 是否能看到谁有空？
- 是否能看到谁超负荷？
- 是否能看到推荐候选人？
- 推荐候选人是否有原因？
- 分配完成后，任务条是否出现在对应人员时间轴？
- 超负荷时是否弹二次确认？
- 普通员工是否不能越权分配？
- manager 是否只能管理自己范围内的人？
