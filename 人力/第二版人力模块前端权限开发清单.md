# 第二版人力模块前端权限开发清单

> 本清单给前端实现使用，来源于 `第二版人力模块详细设计说明.md`。目标是把第二版图片复刻成真实页面时，避免把超级管理、项目管理、部门管理者、个人用户的入口和数据范围混在一起。
>
> 核心原则：前端可以负责显示和交互裁剪，但最终数据范围和写入权限必须以后端返回的权限与接口校验为准。

## 1. 前端开发目标

前端要实现的是“同一套人力模块，不同角色看到不同入口、不同数据、不同按钮”。

不是做四套完全不同页面，而是在同一套基础组件上，根据当前登录人的 `resourcePermissions` 渲染：

- 视角入口。
- 部门 / 人员树。
- 时间轴数据。
- 空闲池范围。
- 分配按钮。
- 超负荷二次确认按钮。
- 导出、转移、强制分配等管理动作。

## 2. 角色定义

| 角色 | 建议前端枚举 | 页面默认入口 | 数据范围 |
| --- | --- | --- | --- |
| 超级管理 | `super_admin` | 超级管理视角 | 全公司、全部部门、全部项目、全部人员。 |
| 管理 / 项目管理 | `manager` / `project_manager` | 项目管理视角或授权人力总览 | 自己负责或被授权的项目、部门、人员。 |
| 部门管理者 | `department_manager` | 部门管理者视角 | 自己负责的部门；多部门负责人只能在负责部门之间切换。 |
| 普通个人 | `employee` | 个人视角 | 只能看自己、自己的任务、自己的空闲窗口。 |

## 3. 权限数据结构

建议前端在进入人力模块前，先从后端拿到当前用户的人力模块权限。

### 3.1 建议字段

```ts
type ResourceScopeType = 'company' | 'project' | 'department' | 'self' | 'authorized';

interface ResourcePermissions {
  canViewSuperAdminView: boolean;
  canViewProjectManagerView: boolean;
  canViewDepartmentView: boolean;
  canViewOtherPersonView: boolean;
  canViewFreePool: boolean;
  canViewConflictRisk: boolean;
  canCreateAssignmentPreview: boolean;
  canAssignTask: boolean;
  canTransferConflictTask: boolean;
  canForceAssignOverload: boolean;
  canExportReport: boolean;
  scope: {
    type: ResourceScopeType;
    departmentIds: string[];
    projectIds: string[];
    userIds: string[];
  };
}
```

### 3.2 前端使用方式

- 页面入口由 `ResourcePermissions` 决定，不要写死。
- 视角切换按钮由 `canView*` 字段决定，不要所有角色都显示。
- 列表请求必须带上后端允许的范围参数，不能让用户随便传任意 `departmentId` / `projectId` / `userId`。
- 即使前端隐藏按钮，后端接口仍然必须校验；前端不要把隐藏当安全。

## 4. 默认进入视角

| `scope.type` | 默认进入视角 | 前端表现 |
| --- | --- | --- |
| `company` | 超级管理视角 | 显示全公司统计、全部部门树、跨部门时间轴。 |
| `project` | 项目管理视角 | 显示负责项目和项目相关人员，不显示无关部门完整数据。 |
| `authorized` | 授权人力总览 | 显示后端授权范围内的部门、项目和人员。 |
| `department` | 部门管理者视角 | 显示本部门状态、本部门人员、本部门空闲池。 |
| `self` | 个人视角 | 显示本人信息、本人任务、本人空闲窗口。 |

## 5. 左侧视角入口渲染清单

### 5.1 超级管理

参考图片：`05-新版超级管理人力总览.png`

显示入口：

- 超级管理视角。
- 项目管理视角。
- 部门管理者视角。
- 个人视角。
- 空闲池。
- 交互完成态。

显示数据：

- 全公司部门树。
- 全部人员。
- 全部项目相关任务。
- 全公司空闲提醒。
- 全公司超负荷风险。

允许动作：

- 查看任意人员个人视角。
- 在全公司范围内查找可分配人员。
- 确认分配。
- 强制分配超负荷人员，但必须填写原因。
- 导出全公司报表。

### 5.2 管理 / 项目管理

参考图片：`05-新版超级管理人力总览.png`，但数据范围需要收窄。

显示入口：

- 项目管理视角。
- 授权范围内的人力总览。
- 部门管理者视角，如果项目涉及对应部门。
- 个人视角，如果目标成员在负责项目内。
- 空闲池，仅限授权项目 / 部门。
- 交互完成态，仅限自己负责范围。

不显示入口：

- 未授权的全公司超级管理视角。
- 无关部门完整人员树。
- 无关项目的人力数据。

允许动作：

- 给负责项目内任务推荐人员。
- 确认负责项目内任务分配。
- 转移负责项目内冲突任务。
- 强制分配超负荷人员，但必须二次确认并记录原因。
- 导出授权范围报表。

### 5.3 部门管理者

- 超级管理视角。

- 全公司部门树。
- 其他部门空闲池。
- 其他部门完整人员负载。

显示数据：

- 本部门状态卡。
- 本部门人员。
- 本部门时间轴。
- 本部门候选人员。
- 本部门空闲提醒。
- 本部门超负荷风险。

允许动作：

- 查看本部门成员个人视角。
- 在本部门内查找可分配人员。
- 确认本部门成员承接任务。
- 转移本部门内冲突任务。
- 导出本部门负载。

需要限制：

- 跨部门分配任务时，需要项目管理或超级管理确认。
- 默认不允许强制分配其他部门人员。
- 是否允许本部门内强制分配超负荷人员，需要按公司规则配置。

- 本人负载状态。

- 搜索其他人员并打开。
- 给别人分配任务。
- 确认给别人分配。
- 强制分配超负荷人员。
- 转移冲突任务。
- 导出人力报表。

## 6. 页面和组件开发清单

## 6.1 `ResourceView`

职责：

- 人力模块总入口。
- 初始化权限。
- 根据权限决定默认视角。
- 控制当前视角的路由或状态。

开发要求：

- 进入页面先请求 `resourcePermissions`。
- 如果没有权限进入当前 URL 对应视角，自动跳回默认视角或显示无权限页。
- 不要先渲染全量页面再隐藏，避免短暂露出无权限数据。
- 所有子组件通过权限对象决定显示内容。

验收点：

- 普通个人直接访问超级管理 URL，页面不能展示全公司数据。
- 部门管理者直接访问其他部门 URL，页面不能展示其他部门数据。
- 项目管理直接访问未授权项目，页面不能展示未授权项目数据。

## 6.2 `ResourceSidebar`

职责：

- 渲染左侧视角入口。
- 渲染部门 / 人员树。
- 渲染空闲提醒。

开发要求：

- 按 `canViewSuperAdminView` 显示“超级管理视角”。
- 按 `canViewProjectManagerView` 显示“项目管理视角”。
- 按 `canViewDepartmentView` 显示“部门管理者视角”。
- 按 `scope.type !== 'self' && canViewFreePool` 显示“空闲池”。
- `scope.type === 'self'` 时，不显示部门 / 人员树，只显示个人入口。
- 部门管理者只显示自己负责部门及部门成员。

验收点：

- 部门管理者左侧不出现“超级管理视角”。
- 普通个人左侧不出现任何部门列表。
- 超级管理左侧可以看到完整公司部门树。

## 6.3 `ResourceToolbar`

职责：

- 渲染顶部视角模式按钮、搜索、筛选。

开发要求：

- 普通个人模式下，只显示“个人模式 / 我的时间线”之类轻量入口。
- 部门管理者模式下，可以显示“部门模式”，不能显示“全公司模式”。
- 超级管理可以显示完整模式切换。
- 搜索框搜索范围必须由后端授权范围控制。

验收点：

- 普通个人搜索别人姓名，不应返回别人。
- 部门管理者搜索其他部门成员，不应返回。
- 项目管理搜索未授权项目成员，不应返回。

## 6.4 `ResourceTimeline`

职责：

- 渲染人力时间轴主体。

开发要求：

- 根据接口返回的数据渲染，不在前端拼接无权限人员。
- `scope.type === 'self'` 时只渲染本人时间轴。
- `scope.type === 'department'` 时只渲染本部门人员。
- `scope.type === 'project'` 或 `authorized` 时只渲染授权范围。
- `scope.type === 'company'` 时可渲染全公司。

验收点：

- 部门管理者切换日期后，仍然只看到本部门。
- 普通个人切换日期后，仍然只看到本人。
- 项目管理切换筛选后，不能跳出授权范围。

## 6.5 `ResourcePersonPanel`

职责：

- 显示人员详情、任务、负载、沟通记录。

开发要求：

- 打开别人个人视角前检查 `canViewOtherPersonView` 和目标 `userId` 是否在授权范围。
- 普通个人只能打开自己的面板。
- 部门管理者只能打开本部门成员。
- 项目管理只能打开负责项目内成员。

验收点：

- 普通个人通过 URL 访问别人个人视角，前端显示无权限或回到本人。
- 部门管理者不能通过人员 ID 打开其他部门成员详情。

## 6.6 `ResourceAssignmentDrawer`

职责：

- 新建任务推荐人力。
- 展示候选人、推荐原因、分配预览。

开发要求：

- 只有 `canCreateAssignmentPreview === true` 时显示入口。
- 普通个人不显示。
- 部门管理者候选人默认限制在本部门。
- 项目管理候选人限制在负责项目或授权部门。
- 候选人列表直接使用后端返回结果，不在前端自行扩大范围。

验收点：

- 普通个人看不到“查找可分配人员”按钮。
- 部门管理者推荐列表不出现其他部门人员。
- 项目管理推荐列表不出现未授权项目人员。

## 6.7 `ResourceOverloadConfirmDialog`

职责：

- 超负荷二次确认弹窗。

开发要求：

- 只有 `canForceAssignOverload === true` 时显示“仍然分配”。
- 普通个人永远不显示“仍然分配”。
- 部门管理者是否显示取决于公司规则和后端权限。
- 弹窗必须显示分配前负载、分配后负载、冲突任务、推荐替代人员。
- 点击“仍然分配”时必须要求填写原因，或由后端强制校验原因字段。

验收点：

- 普通个人不能触发强制分配。
- 管理 / 项目管理强制分配时出现二次确认。
- 超级管理强制分配时必须记录原因。

## 6.8 `ResourceNodeView`

职责：

- 后续增强的节点关系视图。

开发要求：

- 第一阶段可以不实现。
- 如果实现，节点只展示当前登录人有权限看到的人、项目和任务。
- 普通个人不显示全局节点关系。

验收点：

- 部门管理者节点图不出现其他部门完整人员链路。
- 普通个人节点图只显示和本人相关的节点。

## 7. 路由守卫清单

前端路由要做基础拦截，但不能代替后端权限。

| 路由场景 | 前端处理 |
| --- | --- |
| 访问超级管理视角 | 检查 `canViewSuperAdminView`，无权限则跳默认视角或显示无权限。 |
| 访问项目管理视角 | 检查 `canViewProjectManagerView` 和项目授权。 |
| 访问部门视角 | 检查 `canViewDepartmentView` 和 `departmentId` 是否在 `scope.departmentIds`。 |
| 访问个人视角 | 如果目标不是本人，检查 `canViewOtherPersonView` 和 `scope.userIds`。 |
| 访问空闲池 | 检查 `canViewFreePool`。 |
| 打开分配抽屉 | 检查 `canCreateAssignmentPreview`。 |
| 打开强制超负荷确认 | 检查 `canForceAssignOverload`。 |

建议无权限处理：

- 管理类视角：显示“无权限查看该人力视角”，并提供返回默认视角。
- 个人视角：如果访问别人无权限，回到自己的个人视角。
- 弹窗动作：隐藏按钮优先；如果接口返回无权限，再弹错误提示。

## 8. 接口调用清单

## 8.1 初始化权限

页面进入时调用：

```http
GET /workspace/resources?department=&q=&status=active
```

前端需要读取：

- `resourcePermissions`
- `scope`
- `departments`
- `people`

前端处理：

- 根据 `scope.type` 设置默认视角。
- 根据 `resourcePermissions` 渲染入口。
- 根据返回的 `departments` / `people` 渲染树，不自行补全全公司数据。

## 8.2 查询负载

```http
GET /workspace/workload?from=2026-05-10&to=2026-06-14&projectId=&department=&userId=
```

前端处理：

- 查询参数必须来自当前视角和授权范围。
- 不要让 URL 参数直接覆盖权限范围。
- 如果后端返回无权限，清空当前页面敏感数据并提示。

## 8.3 分配预览

```http
POST /workspace/assignments/preview
```

前端处理：

- 只有有权限时显示入口。
- 请求候选人范围不能突破 `scope`。
- 候选人结果必须显示推荐原因。
- 如果候选人超负荷，必须引导到二次确认或替代推荐。

## 8.4 确认分配

建议后端提供类似接口：

```http
POST /workspace/assignments/confirm
```

前端处理：

- 只有 `canAssignTask === true` 时允许提交。
- 跨部门任务如果后端返回需要上级确认，前端要显示对应状态。
- 分配完成后刷新时间轴和写入结果。

## 8.5 强制超负荷分配

建议后端提供类似接口：

```http
POST /workspace/assignments/force-confirm
```

前端处理：

- 只有 `canForceAssignOverload === true` 时允许提交。
- 必须提交原因 `reason`。
- 必须展示风险摘要。
- 成功后刷新时间轴，并在完成态展示“强制分配已记录”。

## 10. 前端验收清单

### 10.1 超级管理验收

- 能看到超级管理视角入口。
- 能看到全公司部门树。
- 能看到跨部门人员时间轴。
- 能打开任意人员个人视角。
- 能进入空闲池。
- 能发起推荐、确认分配、二次确认超负荷。
- 强制分配时必须填写原因。

### 10.2 管理 / 项目管理验收

- 能看到项目管理视角或授权人力总览。
- 只能看到负责项目或授权部门的人。
- 不能看到未授权项目完整人力。
- 推荐候选人不出现未授权人员。
- 分配完成态只展示自己负责范围。
- 导出报表只导出授权范围。

### 10.3 部门管理者验收

- 左侧不显示超级管理视角。
- 左侧不显示全公司部门树。
- 只显示自己部门和部门成员。
- 只能查看本部门成员个人视角。
- 本部门空闲池只出现本部门人员。
- 跨部门分配需要上级确认或被拦截。

### 10.4 普通个人验收

- 默认进入个人视角。
- 左侧不显示部门 / 人员树。
- 不显示超级管理、项目管理、部门管理者入口。
- 搜索别人不返回结果。
- 访问别人个人视角会被拦截。
- 不显示推荐分配、确认分配、强制分配、导出报表按钮。

## 11. 常见错误避免

- 不要把第二版图片里的所有视角按钮照搬给所有角色。
- 不要只隐藏按钮但仍然请求全量数据。
- 不要在前端用角色名硬编码全部逻辑，必须以后端权限对象为准。
- 不要让 `departmentId`、`projectId`、`userId` URL 参数突破权限范围。
- 不要给普通个人返回部门树后再前端过滤。
- 不要让部门管理者看到其他部门完整人员负载。
- 不要让项目管理看到未授权项目的人力数据。
- 不要让超负荷强制分配绕过二次确认和原因记录。

## 12. 建议实现顺序

1. 接入 `resourcePermissions` 和 `scope`。
2. 实现 `ResourceView` 默认视角选择。
3. 实现 `ResourceSidebar` 按权限显示入口。
4. 实现 `ResourceTimeline` 按接口返回数据渲染。
5. 实现个人视角权限拦截。
6. 实现部门视角权限拦截。
7. 实现分配推荐入口权限。
8. 实现超负荷二次确认权限。
9. 补路由守卫和接口错误提示。
10. 按四类角色跑验收清单。

## 13. 一句话给前端

先拿 `resourcePermissions`，再决定显示什么；页面上看不到不是安全，接口拿不到才是真的安全。
