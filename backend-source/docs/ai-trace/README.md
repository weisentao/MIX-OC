# AI 后端操作溯源目录

本目录记录每次 AI agent 参与后端改造、验证、文档整理时的操作来源、影响范围和验收结果。任何后端 agent 在开始修改前先阅读本目录，结束前补充一份当轮记录，避免多 agent 并行时出现重复覆盖、接口状态误判或验证口径不一致。

## 记录命名

文件名使用 `YYYY-MM-DD-agent-<编号>-<主题>.md`。如果同一天同一 agent 执行多轮任务，在主题后追加短后缀，例如 `2026-05-15-agent-08-trace-and-contracts-b.md`。文件只记录本轮已完成、已扫描、已验证的事实，不写无法证明的“已上线”结论。

## 必填结构

每份记录必须包含以下一级或二级标题：目标、分工、文件、接口、验证、风险。目标说明本轮交付边界；分工记录主线程或其他 agent 的职责边界；文件列出新增、修改、只读扫描的文件；接口记录前端调用、后端路由、未挂载或未实现差异；验证写明执行过的命令、结果和未执行原因；风险记录上线阻塞、兼容性缺口、后续需要补测的内容。

## 状态标记

接口状态使用三段式描述：`frontend-detected` 表示只读前端扫描发现调用；`backend-module-present` 表示后端模块内已有 route/controller/service；`root-mounted` 表示已被 `src/routes/index.js` 或 `src/app.js` 挂入 Express 主路由。没有 root mount 的接口只能写成“模块已存在，当前主应用入口未挂载”，不能写成“生产可用”。

## 后续记录规范

每轮结束前先确认允许修改范围，再新增本目录下的记录文档。记录中不要复制大段源码，只写路径、接口、命令和结论。遇到其他 agent 正在修改的文件时，只读扫描并在风险里标注，不回滚、不覆盖。验证失败时保留失败命令、失败摘要和建议下一步，不能删除失败信息来制造通过状态。
