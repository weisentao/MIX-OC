## 4. 当前排期主要问题

### 4.1 模型不够

当前排期把排期等同于任务列表中的 `task`，通过 `scheduleStatus` 组织 Kanban 列。PDF 中的排期有更完整的模型：

| PDF 概念 | 当前系统是否有 |
| --- | --- |
| 项目排期计划 | 没有独立表，只用项目日期和任务日期。 |
| 排期环节 | 没有独立实体。 |
| 排期条形时间线 | 没有。 |
| 排期任务与流程任务联动 | 部分有 `type=排期`，但没有联动规则。 |
| 快照历史 | 当前画板有 history，排期没有。 |
| 排期模板库 | 有模板树概念，但没有专门排期模板内容结构。 |
| 导出 HTML/PDF | 没有排期导出。 |
| 浮动聊天框 | 当前任务评论是任务卡内面板，不是可拖动窗口。 |
| 三视图切换 | 当前只有 Kanban/List。 |

### 4.2 UI 不匹配

PDF 主画面是类似甘特图的项目排期：

| 区域 | PDF 预期 |
| --- | --- |
| 顶部标题 | 项目排期、日期范围、项目名称、状态统计。 |
| 工具栏 | 导入模板、保存模板、分享、快照、导出、视图切换。 |
| 视图切换 | 时间线模式、看板模式、节点模式。 |
| 左侧表格 | 部门 / 排期名称 / 流程。 |
| 右侧时间轴 | 周维度 + 日维度 + 周末/节假日高亮。 |
| 中间条形 | 多色排期条、任务条、里程碑、依赖线。 |
| 聊天框 | 可移动浮窗，绑定选中排期或任务。 |
| 缩放按钮 | `+` / `-` 调整视图范围。 |

当前 UI 是工作台风格的三栏排期列表，无法承载完整时间线。

### 4.3 数据同步缺口

当前 `taskPayload()` 会带 `scheduleStatus`、`progress`，但后端 `createTask/updateTask` 没有正式存储这两个字段，只会把部分任务字段写入 `tasks` 表，其他信息可能丢失或只存在前端内存。

正式实现必须处理：

| 字段 | 建议存储位置 |
| --- | --- |
| `scheduleStatus` | `schedule_items.status` 或 `tasks.payload_json` 过渡。 |
| `progress` | `schedule_items.progress`。 |
| 排期条起止日期 | `schedule_items.start_date/end_date`。 |
| 任务条与流程任务关系 | `schedule_items.task_uid`。 |
| 快照 | `schedule_snapshots.snapshot_json`。 |
| 模板 | `schedule_templates.template_json`。 |

## 5. PDF 新排期目标

新排期应该成为项目中的正式排期中心，而不是附属列表。

核心目标：

1. 覆盖旧的 `ScheduleView.vue` 页面。
2. 默认展示 PDF 中的时间线模式。
3. 保留看板模式，但从 Kanban/List 升级成排期看板。
4. 新增节点模式，展示排期节点关系和依赖。
5. 新建排期时可选择部门、起止日期、是否同步到任务和流程。
6. 支持排期模板导入和保存为模板。
7. 支持快照保存、快照历史、快照对比。
8. 支持排期/任务评论，聊天框可浮动和移动。
9. 支持导出 HTML 和 PDF 预览版。
10. 支持时间轴左右移动、回到今天、放大缩小。
