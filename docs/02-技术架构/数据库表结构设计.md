# 数据库表结构设计

> 文档用途：用于向新的开发者或 AI 交接当前 MySQL 数据库设计、表用途、核心字段、索引策略、迁移文件和生产初始化规则。本文是独立文档，可单独阅读。

## 1. 数据库总体说明

| 项 | 内容 |
| --- | --- |
| 数据库类型 | MySQL |
| 默认库名 | `xjg` |
| 字符集 | `utf8mb4` |
| 排序规则 | `utf8mb4_unicode_ci` |
| 存储引擎 | InnoDB |
| 标准 schema | `G:\mutou\xm\xjg-api\src\db\schema.sql` |
| 迁移目录 | `G:\mutou\xm\xjg-api\src\db\migrations` |
| 建表入口 | `src/db/mysql.js` 的 `ensureAuthTables()` 和 `ensureWorkspaceTables()` |

当前阶段数据库设计目标是从旧的整包 JSON 状态逐步迁移到模块化业务表，同时保留 `app_states` 作为兼容 fallback。

## 2. 设计原则

| 原则 | 说明 |
| --- | --- |
| 业务 UID 优先 | 大部分业务表使用 `*_uid` 作为稳定业务 ID |
| 保留 legacy ID | 项目、任务、模板保留旧前端数字 ID 或字符串 ID 以兼容 seed/store |
| 暂不强制外键 | Phase 1 不加硬外键，避免旧 JSON 导入或清理演示数据时被阻断 |
| JSON 扩展字段 | 多数业务表含 `payload_json`，用于承载前端兼容字段和临时扩展 |
| 索引覆盖查询 | 对 UID、状态、排序、关系字段、时间窗口加索引 |
| appState 兼容 | `app_states` 保留，但正式业务应优先走模块化表 |

## 4. 用户与认证表

### 4.1 `users`

用途：认证、角色和个人主页资料的源数据。

核心字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | BIGINT UNSIGNED | 自增主键 |
| `user_uid` | VARCHAR(64) | 用户业务 UID，唯一 |
| `username` | VARCHAR(64) | 登录账号，唯一 |
| `password_hash` | VARCHAR(255) | bcrypt hash |
| `name` | VARCHAR(64) | 显示姓名 |
| `role` | VARCHAR(32) | `admin`、`manager`、`employee`、`user` 等 |
| `status` | VARCHAR(16) | `active`、`archived` 等 |
| `phone` | VARCHAR(32) | 手机号 |
| `email` | VARCHAR(128) | 邮箱 |
| `department` | VARCHAR(64) | 部门 |
| `department_en` | VARCHAR(128) | 英文部门名或展示字段 |
| `job` | VARCHAR(64) | 职位 |
| `mbti` | VARCHAR(16) | MBTI |
| `mood` | VARCHAR(255) | 心情 |
| `signature` | VARCHAR(255) | 签名 |
| `profile_note` | VARCHAR(255) | 个人说明 |
| `character_label` | VARCHAR(64) | 人物标签 |
| `avatar_image` | LONGTEXT | 头像图片，目前可存 base64 |
| `character_image` | LONGTEXT | 人物图 |
| `signature_image` | LONGTEXT | 手写签名图 |
| `last_login_at` | DATETIME | 最后登录时间 |

索引：

| 索引 | 字段 |
| --- | --- |
| `uniq_users_user_uid` | `user_uid` |
| `uniq_users_username` | `username` |
| `idx_users_email` | `email` |
| `idx_users_phone` | `phone` |

种子规则：

- 固定超级管理员：`admin/admin`。
- 真实用户来自 `G:\mutou\文档\用户列表.md`。
- 真实用户默认密码：`MIX801002`。
- 带电脑标记用户为 `manager`，其他为 `employee`。
- 重复账号 `MIX-yuanye` 合并为一条。

### 4.2 `app_states`

用途：兼容旧前端整包状态。

字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | VARCHAR(64) | 当前固定 `main` |
| `data_json` | LONGTEXT | 整包状态 JSON |
| `updated_by` | VARCHAR(64) | 更新用户 |
| `created_at` | DATETIME | 创建时间 |
| `updated_at` | DATETIME | 更新时间 |

注意：该表只作为兼容 fallback。正式上线验收必须以模块化业务表和 `/workspace/*` API 为准。

## 5. 权限与组织表

### 5.1 `departments`

用途：部门字典和通讯录部门筛选。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `department_uid` | 部门 UID |
| `name` | 部门名称，唯一 |
| `name_en` | 英文/展示名称 |
| `parent_department_uid` | 父部门 |
| `manager_user_uid` | 部门负责人 |
| `status` | 状态 |
| `sort_order` | 排序 |
| `payload_json` | 扩展 |

### 5.2 `roles`

用途：系统角色字典。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `role_key` | 角色 key，唯一 |
| `name` | 角色名称 |
| `description` | 描述 |
| `is_system` | 是否系统内置 |

### 5.3 `permissions`

用途：权限点字典。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `permission_key` | 权限 key，唯一 |
| `name` | 权限名称 |
| `description` | 描述 |

### 5.4 `role_permissions`

用途：角色与权限点关系。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `role_key` | 角色 key |
| `permission_key` | 权限 key |

唯一约束：`role_key + permission_key`。

### 5.5 `user_roles`

用途：用户角色关系，可支持全局或局部 scope。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `user_uid` | 用户 UID |
| `role_key` | 角色 key |
| `scope_type` | 默认 `global` |
| `scope_uid` | scope 对象 UID |

唯一约束：`user_uid + role_key + scope_type + scope_uid`。

## 6. 项目相关表

### 6.1 `project_groups`

用途：项目树一级分组。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `group_uid` | 分组 UID |
| `title` | 分组标题 |
| `suffix` | 数字/后缀展示 |
| `status` | 状态 |
| `sort_order` | 排序 |
| `payload_json` | 扩展 |
| `created_by` / `updated_by` | 操作人 |

索引：

- `group_uid` 唯一。
- `status + sort_order` 用于列表排序。

### 6.2 `projects`

用途：项目主体。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `project_uid` | 项目 UID |
| `legacy_project_id` | 旧前端数字 ID |
| `group_uid` | 所属分组 |
| `name` | 项目名称 |
| `status` | `active`、`archived` 等 |
| `owner_text` | 负责人文本 |
| `start_date` | 开始日期 |
| `end_date` | 结束日期 |
| `archived` | 是否归档 |
| `sort_order` | 排序 |
| `payload_json` | 前端兼容字段，如 `group`、`members`、`syncSchedule` 等 |

索引：

- `project_uid` 唯一。
- `group_uid`。
- `status + sort_order`。
- `legacy_project_id`。
- `name`。
- `archived`。

### 6.3 `project_members`

用途：项目成员和项目内角色。

核心字段：

| 字段 | 说明 |
| --- | --- |
| `member_uid` | 成员关系 UID |
| `project_uid` | 项目 UID |
| `user_uid` | 用户 UID，可为空以兼容旧姓名成员 |
| `member_name` | 成员显示名 |
| `member_role` | `manager`、`editor`、`readonly` |
| `department` | 部门 |
| `department_en` | 部门展示 |
| `status` | 状态 |
| `joined_at` | 加入时间 |
| `payload_json` | 扩展 |

唯一约束：`project_uid + user_uid + member_name`。
