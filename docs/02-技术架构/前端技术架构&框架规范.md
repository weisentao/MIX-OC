# 前端技术架构&框架规范

> 文档用途：本文件用于交接前端工程 `G:\mutou\xm\xjg` 的技术栈、目录职责、状态模型、API 调用方式、组件规范、编码规范和构建验收方式。本文档可单独交给后续前端开发或 AI 接手。

## 1. 工程定位

前端工程是 MIX 项目任务清单与协作工作台的单页应用，负责登录、首页、项目树、流程任务、排期中心、模板、标签、通讯录、成员权限、个人主页、后台管理和协作画板等界面与交互。

工程路径：

```text
G:\mutou\xm\xjg
```

当前状态：

- 已从纯本地 seed 原型推进到可联调后端的 Vue 应用。
- 业务数据优先通过 `/workspace/bootstrap` 和 `/workspace/*` 模块化接口加载。
- 后端同步失败时仍保留本地状态体验，但正式上线不能依赖本地 fallback。
- UI 和交互覆盖较广，但权限、上传、实时协作和 AI 能力仍需继续完善。

## 6. HTTP 与 API 封装

### 6.1 统一 HTTP

位置：`src/services/http.js`

规范：

- baseURL 使用 `import.meta.env.VITE_API_BASE_URL || "/api"`。
- 超时时间为 `15000ms`。
- 请求头默认 `Content-Type: application/json`。
- 请求拦截器自动读取 `localStorage.xjg_token` 并写入 `Authorization: Bearer <token>`。
- 响应拦截器只返回 `response.data`。
- 错误优先取 `error.response.data.message`，否则取 axios 错误消息。

### 6.2 认证服务

位置：`src/services/auth.js`

封装函数：

| 函数 | 后端接口 | 说明 |
| --- | --- | --- |
| `login(username, password)` | `POST /login` | 登录，失败时尝试本地 fallback。 |
| `register(payload)` | `POST /register` | 注册，后端 404 或不可用时创建本地账号。 |
| `getSecurityQuestion(username)` | `GET /security-question` | 兼容旧密保问题流程，当前后端返回未启用。 |
| `forgotPassword(payload)` | `POST /forgot-password` | 找回密码，优先手机号路径。 |
| `changePassword(payload)` | `POST /change-password` | 已登录改密，需要 token。 |
| `getCurrentUser()` | `GET /me` | 获取当前用户。 |

### 6.3 工作台 API

位置：`src/services/workspaceApi.js`

封装范围：

- `getBootstrap()`
- project groups CRUD
- projects CRUD
- project tasks CRUD
- task comments
- tags CRUD
- boards CRUD
- board shares
- board history

规范：

- 所有 path 通过 `encodeURIComponent` 安全拼接。
- 新增模块化 API 时优先放在 `workspaceApi`，组件或 action 不直接写裸 axios。
- 接口路径优先使用 `/workspace/*` 变体，以减少后端根路径和前端代理的耦合。

## 7. 状态管理架构

### 7.1 Store 入口

位置：`src/stores/workspace.js`

```js
export const useWorkspaceStore = defineStore("workspace", {
  state: () => createInitialState(),
  getters: workspaceGetters,
  actions: workspaceActions
});
```

状态来源：

- 初始状态来自 `src/data/seed.js` 的 `createInitialState()`。
- 当前生产口径中初始工作台应为空：用户、公告、标签、项目、画板均不默认注入测试业务数据。

位置：`src/stores/workspace/actions`

- 新增业务 action 放入对应拆分文件，不把逻辑塞回 `workspace.js`。

- 高风险写操作应同时在前端 getter/action 和后端接口做权限校验。

## 9. 协作画板前端设计

关键文件：

- `src/features/collab-board/boardModel.js`
- `src/features/collab-board/ExcalidrawIsland.jsx`
- `src/components/boards/CollabBoardOverlay.vue`
- `src/views/BoardCenter.vue`
- `src/stores/workspace/actions/boardActions.js`

设计要点：

- Excalidraw 是 React 组件，通过 `ExcalidrawIsland.jsx` 挂载到 Vue 容器。
- 画板有 scope：项目级 `project:<projectId>`，模块级 `module:<projectId>:<moduleKey>`。
- 画板权限继承项目成员角色，并支持独立共享 `edit` 或 `readonly`。
- 保存采用 `onChange` debounce，当前前端 900ms 后调用 `store.saveActiveBoard()`。
- 每次保存会生成本地历史快照，并同步到后端 `/workspace/boards/:boardId`。
- 后端同步失败时显示失败提示，但本地仍保留当前画板状态。

当前边界：

- 已实现嵌入式画板、画板库、共享、保存、历史版本。
- 尚未实现 WebSocket 实时多人光标、冲突合并、在线成员 presence。

## 10. UI 与交互规范

现有界面风格偏工作台工具型，不是营销落地页。后续改动应遵循：

- 第一屏直接进入可用工作台，不新增无关营销页。
- 业务操作按钮优先使用图标按钮或短文案，复杂说明放在 tooltip 或弹窗里。
- 项目、任务、排期、画板等固定格式元素应保持稳定尺寸，避免 hover 或文案变化导致布局跳动。
- 弹窗用于表单和管理，不要把页面 section 做成层层嵌套卡片。
- 首页、项目面板、工作区、后台统计都应保持信息密度，避免大面积装饰元素。
- 对只读、编辑、管理等权限状态，必须通过按钮 disabled、提示和后端接口同时约束。

## 11. 编码规范

### 11.1 Vue 组件

- 优先使用 `<script setup>`。
- 组件内部只处理展示和轻量交互，复杂业务放到 Pinia actions。
- props 和 emits 保持明确，避免跨层级直接操作 DOM。
- 表单弹窗保持单向输入、提交时调用 store action 或服务方法。

### 11.2 Store 与数据

- 所有业务字段都要考虑空数组、空对象和后端空工作台返回。
- 从后端加载的数据必须经过 `normalizeLoadedState()` 或对应 mapper 修正默认字段。
- 不再新增默认测试项目、测试任务、测试评论、测试画板到生产初始状态。
- 兼容旧 seed 数据时，应明确区分“演示 fallback”和“正式数据库数据”。

### 11.3 API 调用

- 组件不直接 import axios，统一使用 `auth.js` 或 `workspaceApi.js`。
- 写接口失败时必须给用户明确反馈，不可静默吞掉。
- 涉及删除、清空、归档、权限变更的动作必须有确认或明确入口约束。

### 11.4 本地存储

当前使用的 key：

| key | 用途 |
| --- | --- |
| `xjg_token` | JWT token。 |
| `xjg_user` | 当前登录用户快照。 |
| `xjg_local_auth_users` | 前端本地注册 fallback 账号。 |
| `xjg_local_users` | 前端本地注册 fallback 用户资料。 |

生产功能不应依赖本地 fallback 作为主链路。
