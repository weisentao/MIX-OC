# 后台管理重构项目文档

更新时间：2026-05-15

## 1. 项目目标

把当前混在工作台里的 `AdminDialog` 后台弹窗，重构为一套可维护、可扩展、可对接真实后端的管理控制台。

本次后台管理分成两套入口：

| 控制台 | 面向角色 | 数据范围 | 核心定位 |
| --- | --- | --- | --- |
| Admin Console | `admin` 超级管理员 | 全站数据 | 全局用户、权限、项目、任务、排期、画板、模板、标签、公告、归档、系统状态、审计 |
| Manager Console | 普通管理、项目经理、项目管理、部门组长 | 本部门、我的项目、当前项目、负责分组 | 部门/项目运营管理，不开放超级后台能力 |

实现要求：

- 按截图复刻，不做营销页、空白页、占位页。
- 所有功能必须留正式后端接口，不允许把本地 Pinia / `localStorage` 假成功当成最终实现。
- `admin` 和普通管理必须分权限、分范围、分接口裁剪。
- 普通管理里的“项目管理 / 项目经理 / 部门组长 / 分组内项目管理”在对应项目或分组范围内等同项目 `manager` 权限。

## 2. 当前系统结论

当前前端是 Vue 3 + Vite + Pinia + Vue Router + Element Plus：

- 前端目录：`frontend-source`
- 后端目录：`backend-source`
- 前端开发端口：`15173`
- Vite `/api` 代理后端：`http://localhost:13001`

当前后台问题：

- 路由只有 `/login` 和 `/`，没有独立 `/admin` 或 `/manager`。
- 后台入口是 `frontend-source/src/components/dialogs/AdminDialog.vue` 弹窗。
- `WorkspaceView.vue` 同时负责工作台 shell、弹窗总控、状态同步、后台入口，职责过重。
- 后台数据直接横向读取 `workspace` 单体 store，没有独立后台 store / service。
- 当前入口主要靠 `store.isAdmin`，只认 `currentUser.role === "admin"`，普通管理无法进入受限后台。
- `/appState/main` fallback 只能作为兼容兜底，不能作为正式后台验收通过条件。

后续重构方向：

- 新建独立后台 feature，不继续堆大弹窗。
- 优先做路由化或全屏 shell：`/admin/*` 和 `/manager/*`。
- 统一后台 API：`src/services/adminApi.js`、`src/services/managerApi.js`。
- 统一权限派生：`isSuperAdmin`、`isManagementUser`、`adminScope`、`permissions`。

## 6. 视觉复刻规范

两套控制台共用同一套后台视觉语言：

- 左侧深色导航约 `232px`，品牌区为蓝色 `M` 图标 + 控制台名称。
- 当前导航项亮蓝色整条高亮，菜单项有圆点或小图标。
- 顶部白色状态栏，右侧展示数据源、API、DB、appState、当前用户、角色、范围。
- 主内容区浅灰背景，业务内容用白色卡片承载。
- 标题区：黑色粗体大标题 + 灰蓝说明文案。
- 指标卡：小色块文字图标 + 大号数字，保持行高稳定。
- 筛选条：白色圆角卡片，包含 segmented control、筛选胶囊、搜索框、主操作按钮。
- 表格：浅灰表头、细分割线、稳定行高、蓝色链接、状态 pill。
- 右侧详情区：用户、项目、画板、模板、标签、公告、归档对象都要有“当前选中详情 + 操作入口 + 风险/说明”。
- 风险色固定：蓝色=当前/链接/主操作，绿色=启用/成功/正常，红色=风险/删除/阻止，橙色=警告/待确认，紫色=权限/角色。
- 不使用 hero、大面积插画、营销式版式。
- 不做嵌套卡片堆叠，页面区块保持工作台式密度。

## 7. 权限模型

### 7.1 已有基线

后端已有全局角色：

| 全局角色 | 写入 | 删除 | 导出 | 说明 |
| --- | --- | --- | --- | --- |
| `admin` | 是 | 是 | 是 | 超级管理员 |
| `manager` | 是 | 否 | 是 | 普通管理基线，可写/导出，不允许全局破坏性删除 |
| `employee` | 否 | 否 | 否 | 默认普通员工，只读基线 |

项目角色：

| 项目角色 | 能力 |
| --- | --- |
| `manager` | 查看、编辑、管理项目；管理成员权限；管理排期/画板/模板 |
| `editor` | 编辑任务、排期、评论、画板；不能调权 |
| `readonly` | 查看和评论；不能编辑任务、排期、权限 |
| `none` | 无项目访问 |

### 7.2 新后台权限规则

| 身份 | 后台入口 | 数据范围 | 能力 |
| --- | --- | --- | --- |
| `admin` | Admin Console + Manager Console | 全站 | 全部管理、删除、导出、审计、系统状态 |
| 普通管理 | Manager Console | 本部门/负责分组/自己管理项目 | 可写、可导出、可分配项目角色，不可全局删除 |
| 项目 `manager` | Manager Console 项目范围 | 当前项目 | 等同项目管理权限，可管理项目内成员、任务、排期、画板、模板 |
| 项目 `editor` | 不进后台或仅业务页 | 当前项目 | 编辑内容，不调权 |
| `readonly` / `employee` | 不进后台 | 可见项目 | 查看和评论 |

“分组内项目管理权限和管理一样”落地规则：

- 用户是某项目 `manager`：对该项目拥有普通管理能力。
- 用户是项目分组管理者：对该分组内所有项目视为 `manager`。
- 用户是部门组长：对本部门或本组项目视为 `manager`，但不是全局 `admin`。
- 用户是全局 `manager`：可进入普通管理端，但破坏性删除仍不开放。

### 7.3 建议后端返回字段

`GET /me` 建议返回：

```json
{
  "id": "u-xxx",
  "name": "王牧",
  "role": "manager",
  "isSuperAdmin": false,
  "isManagementUser": true,
  "adminScope": "department",
  "managedGroupIds": ["group-visual"],
  "managedDepartmentIds": ["dept-3d"],
  "permissions": [
    "manager:enter",
    "project:update",
    "project:manage_members",
    "schedule:export"
  ]
}
```

前端不得继续只用 `isAdmin` 控制后台入口。新的入口判断：

- `isSuperAdmin === true`：显示 Admin Console。
- `isManagementUser === true` 或有 `manager:enter`：显示 Manager Console。
- 所有按钮和接口仍以后端返回的 `permissions` / scope 裁决为准。

### 7.4 普通管理准入优先级

普通管理不是一个单一角色，而是多个管理身份的并集。后端最终裁决按以下顺序计算范围，能力取并集，但任何身份都不能自动升级为 `admin`：

| 优先级 | 身份来源 | Manager Console 准入 | 可见范围 | 可分配项目角色 | 可重置/停用账号 |
| --- | --- | --- | --- | --- | --- |
| 1 | `role=admin` / `isSuperAdmin=true` | 可进入 Admin Console，也可预览 Manager Console | 全站 | 全部项目角色；可授予 admin | 全部账号，必须审计 |
| 2 | 全局 `role=manager` | 可进入 Manager Console | 后端授权的部门、分组、项目 | 授权范围内 `manager/editor/readonly` | 仅授权部门账号 |
| 3 | 部门组长 / `managedDepartmentIds` | 可进入 Manager Console | 本部门成员、本部门项目 | 本部门项目内 `manager/editor/readonly` | 本部门账号，不能看明文密码 |
| 4 | 分组管理员 / `managedGroupIds` | 可进入 Manager Console | 负责分组内项目 | 分组项目内 `manager/editor/readonly` | 不默认开放，除非同时是部门组长 |
| 5 | 项目 `member_role=manager` | 可进入当前项目管理页 | 当前项目 | 当前项目内 `manager/editor/readonly` | 不开放账号重置，只能邀请/移除项目成员 |

边界规则：

- 普通管理可以分配项目内 `manager/editor/readonly`，但不能授予 `admin`。
- 普通管理不能查看系统状态审计页，不能进入全站归档中心，不能永久删除全站数据。
- 账号密码页只允许“发起重置 / 停用 / 恢复 / 查看记录”，不允许展示、导出、读取明文密码。
- 如果一个用户同时是部门组长和项目 manager，前端展示合并范围，后端每个接口仍按资源单独校验。

## 13. 验收标准

视觉验收：

- Admin 13 页导航、标题、布局、表格、详情区与截图一致。
- 普通管理 14 页导航、顶部胶囊、范围提示、项目/部门页面与截图一致。
- 1600x1000 下优先还原截图；1280 宽桌面不破版。
- 文案不溢出按钮、卡片、表格。

权限验收：

- `admin` 可进入 Admin Console，拥有全站管理。
- `admin` 可预览 Manager Console，但范围裁剪验收必须使用普通管理账号单独验证。
- 普通管理只能进入 Manager Console。
- 普通管理只能看到本部门、负责分组、自己管理/参与的项目。
- 普通管理不能授予 admin，不能查看系统审计，不能全局永久删除。
- 项目内 `manager/editor/readonly` 在任务、评论、排期、画板、模板、归档中口径一致。

接口验收：

- 每个页面加载、筛选、详情、编辑、危险操作都走后端 service。
- 后端失败必须展示错误，不允许静默成功。
- `/appState/main` fallback 不能作为正式后台成功条件。
- 危险操作必须有二次确认、影响预检、审计记录。
