适用范围：`C:\Users\pveadmin\Desktop\mutou\第一版源代码`

上线目标：第一版正式数据库上线版。现有功能必须依赖真实 MySQL 数据库链路完成验收；`/appState/main` fallback 只保留为异常兜底，不作为正式上线通过条件。

当前上线状态：有阻塞时，以 `3306`、`13001`、`15173` 三个端口的真实监听和健康检查结果为准。

## 1. 上线前检查

- 确认前端目录：`C:\Users\pveadmin\Desktop\mutou\第一版源代码\frontend-source`
- 确认后端目录：`C:\Users\pveadmin\Desktop\mutou\第一版源代码\backend-source`
- 确认后端 `.env` 已配置 `JWT_SECRET`、`PORT=13001`、`MYSQL_DATABASE=xjg` 和正式 MySQL 连接信息。
- 确认 MySQL `127.0.0.1:3306` 可连接。
- 确认前端开发验收口径固定为 `http://127.0.0.1:15173`，后端固定为 `http://127.0.0.1:13001`。
- 确认上线前已备份：
  - 当前前端线上 `dist`
  - 当前后端代码/服务目录
  - MySQL `xjg` 数据库

## 2. 一键本地验收启动/检查

推荐先执行一键脚本，统一拉起并检查 MySQL、后端、前端：

```powershell
cd /d C:\Users\pveadmin\Desktop\mutou\第一版源代码\backend-source
powershell -ExecutionPolicy Bypass -File .\scripts\local-stack-acceptance.ps1 -Action start-and-check
```

脚本固定检查以下口径：

- MySQL：`127.0.0.1:3306`
- 后端：`127.0.0.1:13001`
- 前端：`127.0.0.1:15173`
- 后端健康：`GET http://127.0.0.1:13001/health`
- 后端 API 健康：`GET http://127.0.0.1:13001/api/health`
- 前端代理健康：`GET http://127.0.0.1:15173/api/health`

说明：

- 脚本只做启动、等待监听、健康检查和日志留档。
- 脚本不会执行删库、删表、清空数据、杀进程等破坏性动作。
- 若端口已被现有实例占用，脚本只报告现状，不回滚别人的进程。

## 6. `/api` 反代检查

- `/api/` 应反代到后端 `http://127.0.0.1:13001/`
- 示例反代方向：

```nginx
location /api/ {
  proxy_pass http://127.0.0.1:13001/;
  proxy_http_version 1.1;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Forwarded-Proto $scheme;
}
```

- 浏览器 Network 中前端请求应命中 `/api/*`
- `GET http://127.0.0.1:15173/api/health` 应返回后端健康结果
- `/workspace/*` 返回 503 时，说明正式数据库链路未通过；不能用 `/appState/main` fallback 判定上线通过。

- 后端执行 `npm run smoke:production`
- 前端执行 `npm run build` 并部署 `dist`
- 打开前端 `http://127.0.0.1:15173/`
- 确认工作台初始为空状态，不出现测试项目、测试任务、测试评论、测试画板
- 完成真实账号登录、项目/任务/评论/标签/通讯录/画板/后台管理验收

## 8. 回滚方案

- 前端：回滚上一版 `dist`
- 后端：回滚上一版代码/服务目录后重启
- 数据库：仅允许基于备份恢复
- 禁止用删表、清库、覆盖未知来源数据作为回滚手段

- 只有 `3306`、`13001`、`15173` 三端口监听正常，且 `/health`、`/api/health`、前端代理 `/api/health` 全部通过后，才能进入人工验收。
