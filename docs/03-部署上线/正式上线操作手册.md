# 正式上线操作手册

更新时间：2026-05-16 18:00:00 +08:00

本手册用于正式上线前的冻结、部署、验收和回滚。当前阶段是上线准备，不代表已经上线。

## 1. 上线前冻结规则

- UI 改动未完成前不能上线。
- 前端冻结后必须重新执行 `npm run build`，不能复用 UI 调整期间的旧 `dist`。
- 后端必须使用真实 MySQL 链路完成检查和 smoke，`/appState/main` fallback 不能作为正式上线通过依据。
- 正式切换前必须确认 MySQL、`JWT_SECRET`、生产 smoke、前端最终 build 全部通过。
- 上线窗口内禁止临时清库、删表、覆盖未知来源的线上文件。

## 2. 后端上线步骤

后端目录：`G:\mutou\xm\xjg-api`

推荐先做本地整套启动/验收：

```powershell
cd /d C:\Users\pveadmin\Desktop\mutou\第一版源代码\backend-source
powershell -ExecutionPolicy Bypass -File .\scripts\local-stack-acceptance.ps1 -Action start-and-check
```

该脚本固定口径：

- MySQL：`127.0.0.1:3306`
- 后端：`127.0.0.1:13001`
- 前端：`127.0.0.1:15173`
- 健康检查：后端 `/health`、后端 `/api/health`、前端代理 `/api/health`
- 行为限制：只启动、等待监听、检查健康与留日志；不执行删库、删表、清数据、杀进程

1. 修改 `.env`

   关键项：

   ```dotenv
   NODE_ENV=production
   PORT=13001
   JWT_SECRET=替换为生产用长随机值
   MYSQL_HOST=127.0.0.1
   MYSQL_PORT=3306
   MYSQL_DATABASE=xjg
   MYSQL_USER=xjg_app
   MYSQL_PASSWORD=替换为生产数据库密码
   MYSQL_CONNECTION_LIMIT=10
   ```

   要求：

   - `JWT_SECRET` 不能为空，不能使用默认示例值。
   - `MYSQL_DATABASE` 必须为 `xjg`。
   - 生产运行建议使用专用数据库用户，不使用 `root`。

2. 启动 MySQL

   Windows 服务示例：

   ```powershell
   Get-Service | Where-Object { $_.Name -match 'mysql|mariadb' -or $_.DisplayName -match 'mysql|mariadb' }
   Start-Service MySQL80
   Get-NetTCPConnection -LocalPort 3306 -State Listen -ErrorAction SilentlyContinue
   ```

   如果服务名不是 `MySQL80`，替换为实际服务名。

3. 创建数据库 `xjg`

   ```sql
   CREATE DATABASE IF NOT EXISTS xjg
     CHARACTER SET utf8mb4
     COLLATE utf8mb4_unicode_ci;
   ```

4. 执行生产数据库准备

   ```powershell
   cd /d G:\mutou\xm\xjg-api
   npm run db:prepare:production
   ```

5. 启动后端并检查健康状态

   ```powershell
   npm start
   ```

   健康检查：

   ```text
   GET http://localhost:13001/health
   GET http://localhost:13001/api/health
   ```

   前端代理健康检查：

   ```text
   GET http://127.0.0.1:15173/api/health
   ```

6. 执行最终后端验证

   ```powershell
   npm run verify:production
   ```

   该命令会依次执行：

   - `npm run db:check:production`
   - `npm run smoke:production`
   - `npm run smoke:boards`

## 5. 浏览器验收清单

所有验收必须走正式前端入口和 `/api` 反代，不能用 `/appState/main` fallback 作为通过依据。

- 空工作台：首次进入生产工作台应为空状态，无旧测试项目、任务、评论、画板。
- 项目：创建、查看、编辑项目，并刷新后确认恢复。
- 任务：创建、编辑、状态变更，并刷新后确认恢复。
- 评论：新增评论、查看评论列表，并刷新后确认恢复。
- @：评论或任务中的 @ 提及能正确保存和展示。
- 通讯录：部门、联系人、真实用户数据可加载。
- 共享：项目共享或成员权限能保存和恢复。
- 画板共享：画板创建、共享、再次打开和刷新恢复正常。
- 刷新恢复：登录态、工作台数据、项目、任务、评论、共享、画板状态刷新后保持一致。

## 6. 回滚方案

1. 前端 `dist` 回滚

   - 上线前备份当前线上 `dist`。
   - 回滚时恢复上一版 `dist`。
   - 回滚后验证页面可访问、静态资源无 404、`/api/health` 正常。

2. 后端代码回滚

   - 使用上一版后端代码包或上一版提交。
   - 回滚后重启后端服务。
   - 验证 `http://localhost:13001/health` 和核心登录接口。

3. 数据库回滚

   - 数据库只允许通过备份恢复。
   - 不允许随意删库、删表、清表或手工删除生产业务数据。
   - 任何恢复操作前必须确认备份文件、恢复目标、停机窗口和负责人。
