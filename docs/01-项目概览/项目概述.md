## 2. 产品定位

该项目是一个面向视觉包装、项目管理、美术、三维、后期、AIGC 等协作部门的任务清单工作台。核心目标不是通用 Todo，而是围绕“项目、任务、排期、评论、成员、权限、画板、后台管理”组织团队协作。

当前产品形态是单页 Web 应用，主要覆盖以下业务：

| 业务域 | 产品目标 |
| --- | --- |
| 账号入口 | 支持管理员和 MIX 真实用户登录、注册、找回密码、修改密码。 |
| 项目树 | 以一级目录和项目节点组织项目，支持创建、重命名、删除、归档、恢复、置顶和拖拽迁移。 |
| 流程任务 | 按业务模块展示待完成和已完成任务，支持评论、归档、恢复、拖拽排序。 |
| 排期中心 | 以 Kanban/List 形式管理任务排期状态和截止时间。 |
| 标签系统 | 支持全局标签创建、颜色、筛选、绑定项目和删除。 |
| 模板系统 | 支持模板目录、任务模板、排期模板、共享模拟和用模板创建项目。 |
| 成员协作 | 支持通讯录、项目成员、只读/编辑/管理角色和权限面板。 |
| 评论协作 | 支持任务评论、评论搜索、@ 成员提及和评论风险词识别。 |
| 协作画板 | 使用 Excalidraw 嵌入项目/模块画板，支持画板库、共享、权限、保存和历史版本。 |
| 后台管理 | 支持用户列表、轮播公告、统计面板、评论识别、审计展示等管理入口。 |

## 3. 当前整体状态

当前项目已经从前端原型推进到“前端 + Node API + MySQL 表结构 + 部分模块化接口”的半成品阶段。

已完成的关键变化：

- 前端已从纯本地 seed 演示，改为优先通过 `/workspace/bootstrap` 和 `/workspace/*` API 加载与同步业务数据。
- 后端已实现认证、用户 seed、项目/任务/评论/标签/通讯录/共享/画板等数据库接口。
- 数据库已设计正式表结构，并提供生产准备脚本与 smoke 脚本。
- `/appState/main` 仍保留为兼容旧前端整体状态保存的 fallback，但正式上线不能以它作为通过条件。
- 前端默认测试项目、测试任务、测试评论、测试画板已经按上线口径清理，生产初始化目标是空工作台。

仍未完成或仍阻塞的关键点：

- 当前机器 MySQL 未连通，`127.0.0.1:3306` 未监听，生产数据库链路不能验收。
- 后端 `.env` 中 `JWT_SECRET` 仍需改为生产安全随机值。
- 生产上线必须通过 `npm run db:prepare:production`、`npm run verify:production` 和浏览器真实账号验收。
- 权限体系虽有角色模型，但仍需继续确保所有前端 action 和后端接口都按角色拦截。
- 文件上传、真实对象存储、素材容量统计、实时多人画板、AI/MIX 知识库尚未正式实现。

## 5. 前端架构概览

前端是 Vue 3 + Vite 单页应用。

| 层级 | 说明 |
| --- | --- |
| 入口 | `src/main.js` 创建 Vue 应用，注册 Pinia、Router、Element Plus 和全局样式。 |
| 路由 | `src/router/index.js` 使用 hash 路由，仅有 `/login` 和 `/` 两个主路由。 |
| 主工作台 | `src/views/WorkspaceView.vue` 是核心容器，内部根据 `store.activeSection` 切换首页、流程、排期、画板中心等视图。 |
| 状态管理 | `src/stores/workspace.js` 定义 Pinia store，状态来自 `src/data/seed.js`，业务 action 拆分在 `src/stores/workspace/actions/*`。 |
| API 封装 | `src/services/http.js` 统一 axios、token 注入、错误处理；`auth.js` 与 `workspaceApi.js` 分别封装认证和工作台模块接口。 |
| 画板 | `src/features/collab-board/*` 和 `src/components/boards/CollabBoardOverlay.vue` 封装 Excalidraw 画板能力。 |
| UI 组件 | `src/components` 按 layout、tree、tasks、schedule、dialogs、feedback、media、boards 分组。 |

## 6. 后端架构概览

后端是 Node.js + Express API 服务。

| 层级 | 说明 |
| --- | --- |
| 启动入口 | `src/server.js` 校验环境变量，检测 MySQL/Redis，初始化表和 seed，然后监听端口。 |
| App 组装 | `src/app.js` 挂载 CORS、JSON body、请求日志、API 路由、404 和错误处理中间件。 |
| 路由层 | `src/routes/*.routes.js` 聚合 health、auth、appState、workspace 等模块。 |
| 控制器层 | `src/controllers/*.controller.js` 负责请求参数转交、响应和错误传递。 |
| 服务层 | `src/services/workspace.service.js` 和 `src/services/board.service.js` 负责数据库读写、映射、权限判断。 |
| 数据库层 | `src/db/mysql.js` 管理连接池、建表、真实用户 seed；`src/db/schema.sql` 是正式表结构。 |
| 鉴权 | `src/middlewares/auth.js` 校验 `Authorization: Bearer <token>`，JWT payload 写入 `req.auth`。 |
| 日志 | `src/config/logger.js` 使用 winston 输出控制台、`src/logs/app.log`、`src/logs/error.log`。 |

## 9. 数据流与持久化策略

当前前端加载工作台状态的优先级如下：

```text
WorkspaceView mounted
  -> store.loadAppState()
    -> GET /workspace/bootstrap
      -> 成功：使用模块化数据库数据，backendSource = "workspace"
      -> 失败：GET /appState/main
        -> 成功：使用兼容 appState，backendSource = "appState"
        -> 失败：保留本地 createInitialState() 空状态
```

前端写入策略：

- 项目、任务、标签、画板等主操作会先更新 Pinia 本地状态，随后通过 `workspaceApi` 后台同步。
- 后台同步失败时，前端会提示“已本地保存，后端同步失败”，但正式上线验收不能把这种状态视为成功。
- `/appState/main` 会在旧兼容路径中保存整体 JSON 快照，但它只是兜底，不是正式数据主链路。

## 10. 上线结论

截至本次整理，项目不能声明已正式上线。上线阻塞是环境和生产验收未完成，不是前端界面完全不可用。

上线必须满足：

1. MySQL 服务可连接，数据库 `xjg` 可用。
2. `.env` 中 `JWT_SECRET` 已替换为生产安全随机值。
3. `npm run db:prepare:production` 执行成功。
4. `npm run verify:production` 执行成功。
5. 前端执行 UI 冻结后的最终 `npm run build`。
6. 浏览器使用 `admin/admin` 和真实 MIX 用户完成项目、任务、评论、标签、通讯录、画板的刷新恢复验收。

## 11. 推荐接手顺序

1. 先阅读前端和后端 package、启动脚本、`.env` 示例和当前 README。
2. 启动 MySQL，解决生产检查阻塞。
3. 跑通后端 `db:prepare:production` 和 `verify:production`。
4. 启动前端联调，验证 `/workspace/bootstrap` 返回数据库空工作台。
5. 补齐权限拦截、文件上传、模板 API、画板实时协作等第二阶段任务。
6. 为核心流程沉淀自动化回归测试。
