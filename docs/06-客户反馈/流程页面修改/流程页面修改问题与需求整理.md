## 二、前端修改需求清单

### 1. 禁止从已完成任务列表拖回待完成任务列表

问题现象：当前页面允许或展示了“已完成任务列表”中的任务向左拖拽回“待完成任务列表”的交互意图，但业务要求不允许这样操作。

修改要求：

- 已完成任务不能被拖拽回待完成区域。
- 如果当前有拖拽目标高亮、拖拽占位、可放置状态，需要去掉或禁用。
- 任务从待完成移动到已完成可以保留；反向移动需要禁止。
- 已完成任务列表里的清理、展示逻辑不应影响待完成列表数据。

验收点：

- 从右侧“已完成任务列表”拖动任务到左侧“待完成任务列表”时，无法落入待完成区域。
- 页面刷新后，已完成任务仍停留在已完成列表。
- 待完成列表不会因为拖拽失败出现重复任务或空白卡片。

### 2. 用“项目任务模板”生成项目后，待完成任务列表必须同步带入模板任务

问题现象：在“流程”页面的左侧菜单中，从“项目任务模板”里选择模板，并通过“用模板生成项目”生成项目后，页面中部的“待完成任务列表”没有同步出现模板里的任务。

修改要求：

- 通过项目任务模板生成项目时，要把模板内任务同步生成到新项目的待完成任务列表。
- 模板任务的分组/标签分类需要保留，例如“项目管理”“AIGC”“美术设计”“三维动态”“动效设计”“后期合成”等。
- 任务标题、任务时间、备注或描述、评论入口、详情入口等字段按现有任务卡片结构展示。
- 左侧项目树数量和中部任务列表数量要同步更新。

验收点：

- 点击“用模板生成项目”后，进入生成的新项目，待完成列表不为空。
- 模板里已有的任务全部出现在待完成任务列表中。
- 任务分组数量、任务总数、左侧项目数量显示一致。

### 3. 项目归档必须移动原项目，不要复制镜像

问题现象：当前“项目归档”看起来像复制了一个项目镜像到归档区，原项目仍可能留在“项目汇总”里。业务要求是把“项目汇总”里的项目直接移动到“项目归档”，不是复制。

修改要求：

- 执行项目归档时，原项目从“项目汇总”列表移除。
- 同一个项目在“项目汇总”和“项目归档”中不能同时出现。
- 归档后的项目数据应沿用原项目数据，包括项目名称、任务、完成状态、标签、成员、时间等，不新建无关联副本。
- 如后端有归档状态字段，前端应按归档状态展示位置，而不是按复制数据展示。

验收点：

- 对项目执行归档后，项目汇总中不再显示该项目。
- 项目归档中显示同一个项目，并保留原任务数据。
- 不产生重复项目 ID 或重复项目卡片。

### 4. 项目归档列表需要显示归档时间，并按最新归档时间置顶排序

问题现象：项目归档列表目前只显示项目名称或项目条目，没有清晰显示归档时间；当归档项目数量变多时，需要按归档时间排序。

修改要求：

- 项目归档列表每条记录需要展示归档时间。
- 展示格式参考：左侧项目名称，右侧归档时间。
- 时间格式参考：`2026/04/08 13:20`。
- 多个归档项目按归档时间倒序排列，最新归档的项目在顶部。

建议展示结构：

```text
ABC，大项目                                      2026/04/08 13:20
```

验收点：

- 项目归档中每个项目条目都能看到归档时间。
- 新归档项目出现在项目归档列表顶部。
- 刷新页面后排序保持按归档时间倒序。

### 6. 精简“修改项目”功能入口和弹窗字段

问题现象：“修改项目”入口和弹窗里包含较多功能，PDF 批注认为多余、繁琐。当前“项目汇总”已经支持拖拽，不需要在修改项目里重复提供迁移类功能。

修改要求：

- 左侧项目三点菜单中的“修改项目”可以保留，但进入后的弹窗需要精简。
- 不需要在“修改项目”弹窗中保留“创建到项目汇总 / 创建到分目录”等迁移或创建位置选择功能。
- 不需要保留“主目录名称”等与项目移动位置相关的字段。
- 不需要保留重复的“项目负责人（管理）”展示字段，项目管理信息页面顶部已有。
- 不需要保留“同步到排期，保存后项目时间会同步更新到任务排期范围”这类复杂选项，除非当前业务仍强依赖。
- 保留真正用于编辑项目基础信息的必要字段，例如项目名称、开始时间、结束时间、标签、协同成员。

建议保留字段：

- 项目名称
- 开始时间
- 结束时间
- 标签
- 协同成员

验收点：

- 打开“修改项目”弹窗后，不再看到创建位置选择卡片。
- 不再看到主目录名称、重复项目负责人、同步到排期等被批注划掉的内容。
- 保存修改后，项目基础信息能正常更新。
- 项目移动位置仍通过“项目汇总”里的拖拽完成。

### 7. 标签选择改为加号入口，从标签库选择

问题现象：当前标签字段像是文本输入或拖拽标签区域，批注希望标签最好有一个 `+` 号，通过标签库选择标签。

修改要求：

- 标签区域增加 `+` 入口。
- 点击 `+` 后打开标签库选择面板或下拉选择器。
- 用户从标签库选择已有标签后，标签自动添加到当前项目。
- 尽量避免用户手动输入造成重复标签、错别字或格式不一致。

验收点：

- 项目顶部标签区域或修改项目弹窗的标签字段能看到 `+` 入口。
- 点击 `+` 能看到标签库里的可选标签。
- 选择标签后，项目标签立即显示并可保存。

## 四、建议前端处理优先级

1. 先处理数据逻辑：模板生成项目同步任务、项目归档移动而非复制、归档时间排序。
2. 再处理交互限制：禁止已完成任务拖回待完成列表。
3. 最后处理界面精简：删除顶部图标、精简修改项目弹窗、标签增加 `+` 选择入口。

## 五、需要前后端确认的点

- 项目归档是否已有独立字段，例如 `archivedAt`、`isArchived`、`archiveTime`；如果没有，需要后端新增归档时间字段。
- 模板生成项目时，模板任务复制到项目任务表后，任务 ID 应该是新 ID，但项目来源关系可以保留模板 ID 方便追溯。
- 标签库是否已有接口；如果没有，前端 `+` 入口需要等待标签库接口或先使用本地已有标签数据。
